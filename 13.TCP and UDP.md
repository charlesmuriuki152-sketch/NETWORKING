# Lab 01: Identifying Listening TCP and UDP Ports

## 1. Overview

This lab introduces the basics of TCP and UDP port inspection using built-in Windows networking tools.

The purpose is to identify TCP ports in the listening state, inspect local UDP endpoints, and understand how these observations relate to network communication and security.

This is a beginner-friendly networking lab performed on a local Windows system.

## 2. Objectives

By completing this lab, I learned how to:

* Identify TCP ports in the listening state.
* Inspect local UDP endpoints.
* Use `netstat` to examine network connections and endpoints.
* Understand the difference between TCP and UDP.
* Recognize the role of port numbers in network communication.
* Understand why a listening port does not necessarily mean a service is accessible over the internet.

## 4. Background Theory

### What is a port?

A port is a logical endpoint used by network applications to communicate.

TCP and UDP use port numbers ranging from 0 to 65535.

Some commonly encountered ports include:

| Port | Protocol | Common service          |
| ---: | -------- | ----------------------- |
|   20 | TCP      | FTP data, traditionally |
|   21 | TCP      | FTP control             |
|   22 | TCP      | SSH                     |
|   25 | TCP      | SMTP                    |
|   53 | TCP/UDP  | DNS                     |
|   80 | TCP      | HTTP                    |
|  123 | UDP      | NTP                     |
|  443 | TCP      | HTTPS                   |
|  443 | UDP      | HTTP/3 over QUIC        |
|  445 | TCP      | SMB                     |

These are common assignments, not guarantees that a particular service is running on a given port.

### What is TCP?

Transmission Control Protocol (TCP) is connection-oriented. It establishes a connection before exchanging application data and provides reliable, ordered delivery of a byte stream.

A TCP server can place a socket into a listening state while waiting for incoming connection requests.

### What is UDP?

User Datagram Protocol (UDP) is connectionless. It allows applications to send individual datagrams without establishing a TCP-style connection first.

UDP does not guarantee delivery, ordering, or duplicate protection.

UDP endpoints can be bound to local ports, but UDP does not have a TCP-style `LISTENING` state.

### What does a listening port mean?

A listening TCP port indicates that a local TCP socket is waiting for incoming connection requests.

However, this does not automatically mean that the service can be reached from another device. Accessibility may depend on:

* The local firewall.
* The network interface to which the service is bound.
* Routing and network configuration.
* Firewall rules on intermediate devices.
* Whether the service is running correctly.

## 5. Lab Procedure

### Task 1: Identify listening TCP ports

**Step 1:** Open Windows Command Prompt.

Press `Win + R`, type `cmd`, and press Enter.

**Step 2:** Execute the following command:

```cmd
netstat -an | findstr LISTENING
```

**Step 3:** Examine the output.

Example output:

```text
Proto  Local Address          Foreign Address        State
TCP    0.0.0.0:135            0.0.0.0:0              LISTENING
TCP    0.0.0.0:445            0.0.0.0:0              LISTENING
TCP    127.0.0.1:5000         0.0.0.0:0              LISTENING
```

*Note: This is illustrative output. Actual results depend on the computer and its running services.*

#### Understanding the output

* **Proto:** The transport protocol.
* **Local Address:** The local IP address and port.
* **Foreign Address:** The remote endpoint, if applicable.
* **State:** The current TCP connection state.

#### Understanding the local addresses

* `0.0.0.0:135` means a socket is bound to port 135 on all local IPv4 interfaces.
* `127.0.0.1:5000` means a socket is bound to port 5000 on the loopback interface, making it locally accessible through that address.

A service bound only to `127.0.0.1` is not directly listening on the computer's other network interfaces.

### Task 2: Inspect UDP endpoints

**Step 1:** In Command Prompt, execute:

```cmd
netstat -an -p udp
```

**Step 2:** Examine the output.

Example:

```text
Proto  Local Address          Foreign Address
UDP    0.0.0.0:5353           *:*
UDP    127.0.0.1:1900         *:*
```

*Note: These entries are examples, not results from an actual measurement.*

#### Understanding the output

* **UDP:** Identifies the transport protocol.
* **Local Address:** Shows the local IP address and port associated with the UDP endpoint.
* **Foreign Address:** May appear as a wildcard when the endpoint is not associated with a specific remote peer.

UDP does not use the TCP `LISTENING` state. Therefore, UDP endpoints should be inspected separately.

### Task 3: Filter for a specific port

To search for entries containing port 443, execute:

```cmd
netstat -an | findstr ":443"
```

This is a basic text search. It may match established connections and other entries, not just listening sockets.

To check specifically for a TCP socket listening on port 443, open PowerShell and execute:

```powershell
Get-NetTCPConnection -State Listen -LocalPort 443
```

If a matching listening socket exists, PowerShell returns information about it.

If no result is returned, no matching listening socket was found at the time of the query.

This does not establish whether a service on another computer is reachable at port 443.

## 6. Observations

The following observations describe how the commands work. They are not claimed measurements from a particular computer.

1. The TCP command filters for entries in the `LISTENING` state.
2. The UDP command displays local UDP endpoints separately.
3. TCP and UDP use independent transport-layer port spaces. For example, TCP port 53 and UDP port 53 are distinct endpoints.
4. A local address can indicate whether a service is bound to the loopback interface or to other local interfaces.
5. Port numbers alone do not reliably identify the application using a port.

## 8. Security Considerations

Listening ports are a normal part of computer networking. Their presence does not automatically indicate a security vulnerability.

However, unnecessary or improperly configured services may increase a computer's exposure to network-based attacks.

Good security practices include:

* Disable services that are not needed.
* Keep the operating system and network applications updated.
* Use firewall rules appropriate to the system.
* Avoid exposing administrative services unnecessarily.
* Investigate unexpected listening ports before deciding whether they are a problem.
* Test only systems you own or have permission to assess.

A service listening on all local IPv4 interfaces may be reachable from other devices, depending on the network and firewall configuration. A service listening only on the loopback interface is generally intended for local communication.

## 9. Limitations

This lab is an introductory inspection exercise.

It does not establish:

* Whether a port is reachable from another computer.
* Whether a firewall allows incoming connections.
* Whether the application listening on a port is vulnerable.
* Whether a service is accessible from the public internet.
* Whether a particular port number is being used by its traditionally assigned service.

Further testing in an authorized lab environment would be required to investigate those questions.
