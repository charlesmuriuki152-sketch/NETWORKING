## LAB 1
# Cisco Packet Tracer: The Client Interaction

## 1. Overview

This lab demonstrates how a client computer communicates with a server to request and receive a webpage using **DNS and HTTP**.

Using Cisco Packet Tracer's Simulation Mode, I observed how a domain name is resolved into an IP address, how an HTTP request is sent, and how the server delivers the requested webpage.

## 2. Objectives

* Understand client–server communication.
* Observe DNS domain name resolution.
* Understand how HTTP requests and delivers webpages.
* Examine network events using Simulation Mode.
* Explore PDUs and their relationship to the OSI model.

## 3. Network Topology

The network consists of:

* **PC (Client):** Requests a webpage using a web browser.
* **Server:** Provides DNS and HTTP services.
* **Network connection:** Connects the PC directly to the server.

### Communication Flow

```text
PC (Client)                 Server
     |                         |
     |------ DNS Query ------->|
     |<----- DNS Response -----|
     |                         |
     |----- HTTP Request ----->|
     |<---- HTTP Response -----|
     |                         |
     Webpage displayed
```

## 4. Procedures

1. Open the Packet Tracer activity and enter **Simulation Mode**.
2. Configure the Event List Filters to display DNS and HTTP events.
3. Open the PC's **Desktop** tab and launch the Web Browser.
4. Enter `www.example.com` and click **Go**.
5. Start the simulation and observe the events.
6. Open the PDU Information window to examine the protocol layers and packet details.

## 5. Key Observations

* **DNS** resolves a domain name into an IP address.
* **HTTP** allows the client to request a webpage from the server.
* **TCP** provides reliable, ordered delivery for the HTTP exchange in this activity.
* **Simulation Mode** helps visualize the sequence of network events.
* **PDU Information** provides details about the protocols involved in communication.
